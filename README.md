# FPLwager admin

The admin app for FPLwager, as its own Flutter project. It talks to the same
API as the main app, through the `/v1/admin/...` endpoints.

Administrators sign in here with an **email and password** — there is no FPL
step. The main app no longer has an admin sign-in.

## First-time setup

This folder contains the Dart code (`lib/`), `pubspec.yaml` and a small test.
The platform folders (`android/`, `ios/`, `web/` ...) are generated by Flutter
on your machine:

```bash
cd fpl_wager_admin
flutter create . --project-name fpl_wager_admin --platforms=android,ios,web
flutter pub get
flutter run --dart-define=API_BASE_URL=http://35.217.63.208
```

`flutter create .` only adds what is missing; it keeps `lib/` and
`pubspec.yaml` as they are.

Use the same `API_BASE_URL` as the main app. If you leave it out, the app uses
the address written in `lib/core/config/app_config.dart`.

### Android

Copy two things from the main app's `android/app/src/main/AndroidManifest.xml`
into this project's:

- the internet permission:
  `<uses-permission android:name="android.permission.INTERNET"/>`
- if your API address starts with `http://` rather than `https://`,
  `android:usesCleartextTraffic="true"` on the `<application>` tag.

### Use the same package versions as the main app (recommended)

`pubspec.yaml` lists the packages as `any`, which works, but may pick newer
versions than the main app uses. To match it exactly, open the main app's
`pubspec.yaml`, copy its version numbers for `flutter_riverpod`, `go_router`,
`dio`, `flutter_secure_storage`, `intl` and `uuid` into this project's
`pubspec.yaml`, then run `flutter pub get` again.

## Creating the first administrator

The first administrator (the superadmin) is created on the server, not in the
app:

```bash
# on the server, inside services/api (with the same .env the API uses)
go run ./cmd/createsuperadmin     # asks for email, full name and password
```

Sign in to the admin app with that email and password. From **Users → Add
user** a superadmin can then create more administrators.

## What the app does

| Section | What you can do |
|---|---|
| Users | Add a user, edit name / phone / status / role, add or deduct money, send a notification, delete permanently |
| Pools | Create, **approve** pools users created, edit, change status, see and remove entries, delete |
| Wallets | See balances, **add money** or deduct it (with a reason) |
| Payments | Re-verify with the provider, delete a record |
| Transactions | The ledger, read-only |
| Head to head | View and delete challenges |
| FPL teams | View linked teams, unlink one |
| Notifications | Send a message to a user, delete one |
| System settings | Create, edit and delete settings |
| Gameweeks | The FPL calendar, read-only |
| FPL sign-ins | Everything FPL returned at each sign-in (tokens removed) |
| Audit trail | Every administrator action, read-only |

The football icon at the top of the dashboard opens **My FPL team**, where an
administrator links their own FPL team by its ID.

### What deleting does

Deleting removes the record and everything that belongs to it:

- **A user** — their wallet, ledger, payments, FPL team, pool entries,
  challenges they created, notifications and sessions. Pools they created are
  kept (without an owner) so other managers' entries are not lost.
- **A pool** — its entries. If the pool is not settled, every paid entry is
  refunded first.
- **A challenge** — if it is still open, the challenger is refunded first.
- **A payment record** — only the record; money it already credited stays.

Cancelling a pool (status → cancelled) also refunds every paid entry.

To block someone without losing their records, set their status to
`deactivated` or `banned` instead of deleting them.

## Layout

```
lib/
  main.dart
  app/            app shell, routes, theme
  core/           config, API client, secure session storage, shared widgets
  features/
    auth/         sign-in (email + password)
    admin/        dashboard, lists, user page, FPL team page, API calls
```
